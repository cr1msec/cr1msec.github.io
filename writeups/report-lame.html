Lame

HTBEasyFTPSMBRCE

Lame was compromised by exploiting outdated FTP and Samba services. The vulnerable Samba 3.0.20 service allowed remote code execution and resulted in a root shell.

Solved: July 29, 2026

Recon

Started with a basic Nmap scan:

nmap
$ nmap -sC -sV -Pn 10.129.14.169

Open ports:

PortService
21FTP
22SSH
139SMB
445SMB

The FTP server was running vsftpd 2.3.4, while SMB was running Samba 3.0.20-Debian.

Enumeration

Anonymous FTP login was allowed:

ftp
$ ftp 10.129.14.169

Although anonymous access was successful, no useful files were found.

The outdated vsftpd 2.3.4 version was then identified as potentially vulnerable to CVE-2011-2523.

Further enumeration revealed:

Samba 3.0.20-Debian

This version of Samba is vulnerable to CVE-2007-2447, which allows remote command execution through a malicious username.

Initial Access

The Samba vulnerability was exploited using Metasploit:

msfconsole
$ msfconsole

After configuring the appropriate Samba exploit module and targeting the machine, a shell was obtained.

Privilege Escalation

The Samba exploit provided command execution as root, so no additional privilege escalation was required.

Root

After successfully exploiting the vulnerable Samba service:

whoami root

The root flag was:

f360fc149e6309584eaf37a4b5372362

The user flag was:

48f528f4e6d64ddeb38ab0b6f2f0b739

Key Takeaways

  • Always enumerate all exposed services and their versions.
  • Anonymous FTP access does not necessarily mean useful files will be available.
  • Outdated service versions can reveal known vulnerabilities.
  • Samba 3.0.20 is vulnerable to remote command execution.
  • Successful exploitation of the Samba vulnerability provided a root shell directly.
