Knife

HTBEasyWebSQLiLinux PrivEsc

Knife is an easy Linux machine where an exposed PHP 8.1.0-dev backdoor provides initial access as james. A sudo misconfiguration then allows james to execute Chef's knife utility as root, which can execute Ruby code and provide a root shell.

Solved: July 30, 2026

Recon

Started with a basic Nmap scan:

nmap
$ nmap -sC -sV -Pn 10.129.15.27

The scan identified two accessible services:

PortServiceVersion
22SSHOpenSSH 8.2p1 Ubuntu 4ubuntu0.2
80HTTPApache httpd 2.4.41

The target is running Ubuntu Linux with an Apache web server.

Enumeration

HTTP - TCP 80

Navigating to the website showed a page titled:

Emergent Medical Idea

There were no obvious login pages or useful links.

We could further enumerate the web server with directory fuzzing, but the interesting information came from inspecting the HTTP response.

The response contained the following header:

X-Powered-By: PHP/8.1.0-dev

The -dev suffix is significant because this specific development version of PHP was distributed with a backdoor.

Searching for known vulnerabilities revealed a PHP 8.1.0-dev User-Agentt remote code execution backdoor. The backdoor allows commands to be executed through a specially crafted HTTP User-Agentt header.

Initial Access

We exploited the PHP 8.1.0-dev backdoor to obtain a shell on the target.

The resulting access was as the user:

james

We verified the current user:

whoami
$ whoami
james

We then located the user flag:

6dfb7e73c4400d1eb3a78c739974c930

At this point, we had successfully obtained user-level access.

Privilege Escalation

With access as james, we checked which commands could be executed with sudo:

sudo
$ sudo -l

The output showed:

Matching Defaults entries for james on knife: env_reset, mail_badpass, secure_path=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/snap/bin User james may run the following commands on knife: (root) NOPASSWD: /usr/bin/knife

This meant james could execute /usr/bin/knife as root without entering a password.

We then inspected the binary:

ls
$ ls -l /usr/bin/knife

It was a symbolic link:

/usr/bin/knife -> /opt/chef-workstation/bin/knife

knife is a command-line utility from Chef used to manage Chef infrastructure. It is implemented using Ruby and supports executing Ruby code.

This made the NOPASSWD sudo permission particularly interesting.

Root

Since knife can execute Ruby code, we could use its exec functionality to execute a shell.

The command is:

sudo
$ sudo knife exec -E 'exec "/bin/sh"'

Because knife was being executed through sudo as root, the resulting shell inherited root privileges.

We could then verify our privileges:

id
$ id

The resulting shell had root privileges.

The root flag was:

65624694a835212d40471b89225538c7

Key Takeaways

  • Inspect HTTP response headers. The X-Powered-By header exposed the unusual PHP/8.1.0-dev version that led to the initial access path.
  • Development versions can be dangerous. The PHP 8.1.0-dev release contained a backdoor capable of remote command execution.
  • Always check sudo -l. The james account had passwordless sudo access to /usr/bin/knife.
  • Understand what privileged binaries can do. knife is a Ruby-based utility capable of executing Ruby code, making the unrestricted sudo permission dangerous.
  • A sudo misconfiguration can provide direct root access. No separate kernel or filesystem privilege escalation was necessary.
