Cap

HTBEasyFTPCapabilities

FTP creds leaked through a web app's packet-capture feature, reused over SSH, then a root shell via a Python binary with cap_setuid set.

Solved: July 26, 2026

Recon

Started with a basic Nmap scan:

nmap
$ nmap -sS 10.129.13.60

Open ports:

PortService
21FTP
22SSH
80HTTP

The web application exposed several endpoints, including /capture, /ip, and /netstat. The /capture functionality generated a packet capture file, which could then be downloaded.

Credential Discovery

Inspecting the packet capture revealed FTP credentials:

nathan : Buck3tH4TF0RM3!

These credentials also worked for SSH:

ssh
$ ssh nathan@10.129.13.60

After logging in:

$ whoami nathan $ id uid=1001(nathan) gid=1001(nathan) groups=1001(nathan)

Privilege Escalation

While enumerating the web application, app.py contained a Python command that executed tcpdump with elevated privileges. The important discovery was that Python had dangerous Linux capabilities:

getcap
$ getcap /usr/bin/python3.8
/usr/bin/python3.8 = cap_setuid,cap_net_bind_service+eip

cap_setuid allows a process to change its user ID. Since Python can execute arbitrary code, having cap_setuid effectively allows privilege escalation to root.

Root

The cap_setuid capability could be abused to change the Python process's UID to 0 (root), providing a root shell.

Key Takeaways

  • Enumerate all exposed web functionality, not just the homepage.
  • Packet captures can contain sensitive credentials.
  • Reused credentials can provide SSH access.
  • Always check binaries for Linux capabilities with getcap.
  • cap_setuid on an interpreter such as Python is a major privilege-escalation opportunity.
