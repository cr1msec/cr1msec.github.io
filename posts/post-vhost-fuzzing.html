Virtual Host Fuzzing

MethodWebEnumeration

The real attack surface is often invisible from the main site. Here's why, and how to actually find it.

One IP, multiple websites

A single web server can host several completely different websites on the same IP address and port. Which one you see depends on the Host header your request sends — the server reads that header and routes you to the matching virtual host configuration. If you just visit an IP address or the "obvious" hostname directly, you only ever see whichever site is configured as the default.

Why this matters offensively

Directory brute-forcing (finding hidden paths on one known site) is a familiar step in most enumeration workflows. Virtual host fuzzing is the same idea applied one level higher — instead of asking "what hidden pages exist on this site," it asks "what other sites exist on this server that I haven't found yet." The main site can be completely locked down and give up nothing interesting, while a second, undiscovered vhost on the same box is running an entirely different — and much less hardened — application.

What actually tips you off

A wildcard TLS certificate is one of the strongest signals. A certificate issued for *.example.com instead of just example.com is the server operator telling you, indirectly, that more than one subdomain is expected to exist. That's a direct invitation to go looking for what those subdomains actually are.

How the fuzzing works

The technique sends the same request to the same IP repeatedly, changing only the Host header each time — checking which values produce a different response than the default site:

ffuf
$ ffuf -u https://target/ -H "Host: FUZZ.target.htb" -w subdomains.txt -fs BASELINE_SIZE

The -fs flag filters out responses matching the default site's response size, so what's left in the results are the Host header values that actually produced something different — real, distinct virtual hosts the server is willing to route to.

Why the found subdomain is often the actual target

The main domain is frequently the polished, public-facing marketing site — exactly the part most likely to have received security attention. A subdomain like internal-tool.target.htb or staging.target.htb, found only through fuzzing, is far more likely to be an internal application, an admin panel, or a dev/staging deployment that was never meant to be discoverable — and treated with correspondingly less care.

The general lesson

"I checked the website and there's nothing there" usually means "I checked one website hosted at that IP." Wildcard certificates, unusual DNS records, or even just a server that seems oddly locked-down for how little it does are all reasons to ask what else might be sharing that infrastructure — and vhost fuzzing is the direct way to find out.
